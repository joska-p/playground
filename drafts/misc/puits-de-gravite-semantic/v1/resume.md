### Type 1 : Résumé style manifeste (accessible, moins de jargon)

**English**

# The Semantic Gravity Manifesto

A prompt is not an instruction manual. It is a gravitational field. Words have weight. They pull the model's attention in specific directions.

Writing "do not do X" just drags X into the center of the room. You cannot build a universe by listing what it lacks. You build it by defining what exists.

The laws of prompt gravity:

1. Define what exists. A missing word has no mass. The model will not go where you do not point.
2. Repeat what matters. Weave important ideas into multiple sentences to make them heavy.
3. Use tone as a compass. Strict words build strict code. Flowing words build elegant code.
4. Avoid collisions. Do not mix "do this" with "do not do that". Replace bans with stronger positive actions.
5. State facts. Say "The system handles this" instead of "You should do this". Facts ground the model.
6. Write the code you want to see. The model mimics your style. Verbose text generates verbose code.
7. Use rhythm over lists. Tie ideas together in sentences to give them weight naturally.
8. Prime the space. Prepare the model before showing it external links. Set the tone first.

**Français**

# Le manifeste de la gravité sémantique

Un prompt n'est pas un manuel d'instructions. C'est un champ gravitationnel. Les mots ont un poids. Ils tirent l'attention du modèle dans des directions spécifiques.

Écrire "ne fais pas X" traîne simplement X au centre de la pièce. Vous ne construisez pas un univers en listant ce qui lui manque. Vous le construisez en définissant ce qui existe.

Les lois de la gravité du prompt :

1. Définissez ce qui existe. Un mot absent n'a pas de masse. Le modèle n'ira pas là où vous ne pointez pas.
2. Répétez ce qui compte. Tissez les idées importantes dans plusieurs phrases pour leur donner du poids.
3. Utilisez le ton comme boussole. Des mots stricts construisent du code strict. Des mots fluides construisent du code élégant.
4. Évitez les collisions. Ne mélangez pas "fais ceci" avec "ne fais pas cela". Remplacez les interdictions par des actions positives plus fortes.
5. Énoncez des faits. Dites "Le système gère ceci" au lieu de "Tu devrais faire cela". Les faits ancrent le modèle.
6. Écrivez le code que vous voulez voir. Le modèle imite votre style. Un texte verbeux génère du code verbeux.
7. Utilisez le rythme plutôt que les listes. Reliez les idées dans des phrases pour leur donner du poids naturellement.
8. Préparez le terrain. Préparez le modèle avant de lui montrer des liens externes. Définissez le ton d'abord.

### Type 2 : Résumé court (Le pourquoi et le concept de base)

**English**

Prompting fails when we treat language models like human readers. The Semantic Gravity concept fixes this. It treats a prompt as a mathematical field rather than a list of instructions. Words act like mass. They pull the model toward specific outcomes. When you tell a model what not to do, you pull it toward the exact thing you want to avoid. This concept asks you to write prompts as descriptions of an existing system. You define what exists, use facts instead of commands, and write in the exact style you want the code to mimic.

**Français**

L'ingénierie de prompt échoue quand on traite les modèles de langage comme des lecteurs humains. Le concept de Gravité Sémantique corrige cela. Il considère un prompt comme un champ mathématique plutôt qu'une liste d'instructions. Les mots agissent comme une masse. Ils tirent le modèle vers des résultats spécifiques. Quand vous dites à un modèle ce qu'il ne faut pas faire, vous le tirez vers la chose exacte que vous voulez éviter. Ce concept propose d'écrire des prompts comme les descriptions d'un système existant. Vous définissez ce qui existe, utilisez des faits au lieu d'ordres, et écrivez dans le style exact que vous voulez voir imité dans le code.
