# Concept note: the semantic gravity well

Prompt engineering usually treats the model like a reader. That is the wrong mental model. A prompt is a field of mathematical forces in the model's latent space. Words have mass. Each token adds matter and distorts the model's internal logic. Generation is just a trajectory. The next token the LLM generates is the point where the prompt's gravity pulls strongest.

There is a friction problem with the word "don't". Writing "do not do X" adds the mass of X to the center of attention. The model is literally attracted to the prohibition.

## The laws of semantic gravity

Syntax and grammar form the surface. Semantic gravity does not demand that you write like a machine. It demands that you understand human grammar is already a directional structure. A well written text naturally has a strong gravitational mass.

### 1. The law of the exclusive universe

Define what exists instead of what is forbidden. A missing token has no gravitational mass. The agent will avoid using a feature because the mathematical trajectory of the text you wrote does not lead to it.

### 2. The law of density

An isolated concept in a bulleted list has low mass. Weave crucial concepts into multiple sentences to increase their weight. The goal is a well deep enough that the model's logic falls in through natural attraction.

### 3. The law of tone as a coordinate

Tone is a geographical coordinate in the model's latent space. It is not an emotion. Corporate and strict vocabulary activates patterns of legacy, defensive, verbose code. Exploratory vocabulary activates patterns of concise, elegant code. The chosen vocabulary defines the exact space where the code will be born.

### 4. The law of avoiding contradictory forces

Mixing a positive and a negative instruction creates a collision. Telling the model to "write modern code, do not use classes" makes it spend energy fighting itself. Always replace a negative force with a heavier positive force. Say "write modern, functional, hook based code" instead.

### 5. The law of assertion

The verbal mood determines the temporal position and certainty of a statement. The imperative or conditional mood places the action in a hypothetical future subject to conditions. Phrases like "you should use X" or "do Y" leave the agent on standby. The assertive indicative installs an objective fact into the latent space. Statements like "the system handles X" or "the architecture relies on Y" set a stable foundation.

Documentation describes an existing universe. It is not an instruction manual. The active and assertive voice creates a stable mass the model naturally adopts.

### 6. The law of structural mimicry

An LLM agent is autoregressive. It predicts the next sequence by imitating the statistical distribution of what it has just read. If the main documentation uses heavy, defensive, verbose syntax, the agent will generate code filled with defensive guards. You get unnecessary if statements and excessive try catch blocks. If the documentation is concise and elegant, the generated code will inherit this same style. The writing style of the documentation is the first code example the agent analyzes. The semantic contaminator takes precedence over the instruction.

### 7. The law of density through rhythm

You do not need to stack raw keywords to create gravity. Grammar offers natural tools to increase the mass of a concept without degrading readability. Rhythmic enumeration uses syntax to link multiple actions to a single central action. An example is "installation, management, and execution pass through this module". The sentence structure deepens the gravity well instead of brute word repetition.

### 8. The law of the semantic airlock

When a skill points to external documentation, the agent's context must be prepared to receive it in the correct space. Instead of a raw link, the skill includes an assertive priming sentence that defines the tone. The sentence might say "the main documentation defines our functional ecosystem, so apply its self evident principles". This pre-draws the latent space before the agent reads a line of documentation.

# Note de concept : le puits de gravité sémantique

L'ingénierie de prompt traite généralement le modèle comme un lecteur. C'est le mauvais modèle mental. Un prompt est un champ de forces mathématiques dans l'espace latent du modèle. Les mots ont une masse. Chaque token ajoute de la matière et distord la logique interne du modèle. La génération n'est qu'une trajectoire. Le prochain token que le LLM génère est le point où la gravité du prompt tire le plus fort.

Il y a un problème de friction avec le mot "ne pas". Écrire "ne fais pas X" ajoute la masse de X au centre de l'attention. Le modèle est littéralement attiré par l'interdiction.

## Les lois de la gravité sémantique

La syntaxe et la grammaire forment la surface. La gravité sémantique n'exige pas que vous écriviez comme une machine. Elle exige que vous compreniez que la grammaire humaine est déjà une structure directionnelle. Un texte bien écrit possède naturellement une forte masse gravitationnelle.

### 1. La loi de l'univers exclusif

Définissez ce qui existe au lieu de ce qui est interdit. Un token manquant n'a aucune masse gravitationnelle. L'agent évitera d'utiliser une fonctionnalité parce que la trajectoire mathématique du texte que vous avez écrit n'y mène pas.

### 2. La loi de la densité

Un concept isolé dans une liste à puces a une faible masse. Tissez les concepts cruciaux dans plusieurs phrases pour augmenter leur poids. Le but est de créer un puits assez profond pour que la logique du modèle y tombe par attraction naturelle.

### 3. La loi du ton comme coordonnée

Le ton est une coordonnée géographique dans l'espace latent du modèle. Ce n'est pas une émotion. Le vocabulaire d'entreprise et strict active des schémas de code hérité, défensif et verbeux. Le vocabulaire exploratoire active des schémas de code concis et élégant. Le vocabulaire choisi définit l'espace exact où le code va naître.

### 4. La loi de l'évitement des forces contradictoires

Mêler une instruction positive et une négative crée une collision. Dire au modèle "écris du code moderne, n'utilise pas de classes" le pousse à dépenser de l'énergie à se battre contre lui-même. Remplacez toujours une force négative par une force positive plus lourde. Dites plutôt "écris du code moderne, fonctionnel et basé sur des hooks".

### 5. La loi de l'assertion

Le mode verbal détermine la position temporelle et la certitude d'une déclaration. Le mode impératif ou conditionnel place l'action dans un futur hypothétique soumis à des conditions. Des phrases comme "tu devrais utiliser X" ou "fais Y" laissent l'agent en attente. L'indicatif assertif installe un fait objectif dans l'espace latent. Des déclarations comme "le système gère X" ou "l'architecture s'appuie sur Y" posent une base stable.

La documentation décrit un univers existant. Ce n'est pas un manuel d'instructions. La voix active et assertive crée une masse stable que le modèle adopte naturellement.

### 6. La loi de la mimésis structurelle

Un agent LLM est autoregressif. Il prédit la prochaine séquence en imitant la distribution statistique de ce qu'il vient de lire. Si la documentation principale utilise une syntaxe lourde, défensive et verbeuse, l'agent générera du code rempli de gardes défensifs. Vous obtenez des instructions if inutiles et des blocs try catch excessifs. Si la documentation est concise et élégante, le code généré héritera de ce même style. Le style d'écriture de la documentation est le premier exemple de code que l'agent analyse. Le contaminant sémantique prend le pas sur l'instruction.

### 7. La loi de la densité par le rythme

Vous n'avez pas besoin d'empiler des mots-clés bruts pour créer de la gravité. La grammaire offre des outils naturels pour augmenter la masse d'un concept sans dégrader la lisibilité. L'énumération rythmique utilise la syntaxe pour lier plusieurs actions à une seule action centrale. Un exemple est "l'installation, la gestion et l'exécution passent par ce module". La structure de la phrase approfondit le puits de gravité au lieu de répéter bêtement des mots.

### 8. La loi du sas sémantique

Quand une compétence pointe vers une documentation externe, le contexte de l'agent doit être préparé à la recevoir dans le bon espace. Au lieu d'un lien brut, la compétence inclut une phrase d'amorce assertive qui définit le ton. La phrase peut dire "la documentation principale définit notre écosystème fonctionnel, donc applique ses principes évidents". Cela pré-dessine l'espace latent avant que l'agent ne lise une ligne de documentation.
