# Scaffolding Packages

New packages come from `pnpm gen` (which wraps [`turbo gen`](https://turbo.build/repo/docs/guides/generating-code)) through a custom generator at `turbo/generators/`. It creates a package with the same build tooling as `@repo/mosaic-maker`: Vite, React, TypeScript, Tailwind, ESLint, plus Zustand and Zod wired into a demo component.

## Prerequisites

- The working directory is the repo root.
- Dependencies are installed (`pnpm install`).

## Usage

```bash
pnpm gen new-package
```

The generator prompts for a package name (kebab-case, e.g. `my-visualization`). The prompt skips with:

```bash
pnpm gen new-package --args my-visualization
```

## What You Get

The generator creates `packages/<name>/` with:

```
packages/<name>/
├── .gitignore
├── eslint.config.js
├── index.html                       # Vite dev entry point
├── package.json                     # @repo/<name>, deps on @repo/ui + zod + zustand
├── public/
│   └── favicon.svg
├── README.md
├── src/
│   ├── App.tsx                      # Local dev wrapper
│   ├── components/
│   │   └── Demo.tsx                 # Public component, exported via package.json
│   ├── demo.schema.ts               # Zod schema (runtime validation)
│   ├── stores/
│   │   └── demo/
│   │       └── store.ts             # Zustand store (private, getter hooks + setter fns)
│   ├── main.tsx                     # React DOM entry
│   └── styles/
│       └── global.css               # Tailwind v4 + @repo/ui/gruvbox-theme
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.node.json
├── turbo.json
└── vite.config.ts
```

The `Demo` component is the public API; consumers import it via `@repo/<name>/Demo` (declared in `package.json` `exports`).

## After Generation

```bash
pnpm install
pnpm --filter @repo/<name> dev       # start Vite dev server
```

## Adding to the Playground Website

Every package lands on the Astro site as a **discovery page** at `/discoveries/<name>/`, generated by `project-pages`:

```bash
pnpm generate-typedoc-json
pnpm gen:project-pages
```

The generator writes `apps/playground/src/pages/discoveries/<name>.astro` — a thin wrapper over the shared `DiscoveryLayout`:

```astro
---
import { getEntry, render } from 'astro:content';
import DiscoveryLayout from '../../layouts/DiscoveryLayout.astro';
import { App } from '../../../../../packages/<name>/src/App.tsx';
const entry = await getEntry('packages', '<name>');
const { Content } = await render(entry);
---

<DiscoveryLayout entry={entry}>
    <App
        slot="app"
        client:only="react"
    />
    <Content />
</DiscoveryLayout>
```

- `DiscoveryLayout` composes the app showcase (when the package ships `src/App.tsx`), the README `#overview`, and the `#api` reference.
- The App mounts as a `client:only` island; packages without a `src/App.tsx` are generated without the app section.
- The generator skips pages that already exist, so hand-tweaked pages survive regeneration.

## The Generator Source

The custom generator lives at `turbo/generators/`:

```
turbo/generators/
├── config.ts              # Plop generators: new-package + project-pages
└── templates/             # Handlebars templates
    ├── new-package/       # Package scaffold (addMany)
    └── project-pages/     # discovery-page.astro.hbs: per-package page wrapper
```

The `templates/` directory defines what every new package gets. The templates mirror `@repo/mosaic-maker`'s config exactly; only the application code differs.

## Regenerating Discovery Pages

`pnpm gen:project-pages` reads the generated API docs and rewrites any missing page under `apps/playground/src/pages/discoveries/`. Existing pages stay untouched. Run it after `pnpm generate-typedoc-json` whenever a package is added or removed.
