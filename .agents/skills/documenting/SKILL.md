# Documenting packages

Source: `apps/playground/src/content/docs/how-to/documenting-packages.md` and `conventions/12-documentation.md`.
Partially rolled out — only some packages have docs yet; new packages should adopt this system.

## Two halves

- **README** (`packages/<pkg>/README.md`): concept only — title + tagline, purpose, quick start, usage examples, patterns & gotchas. Never an API inventory.
- **API reference**: generated by TypeDoc from TSDoc (`/** */`) on exported symbols — never edited by hand.

## TSDoc rules

- Only exported symbols consumers touch.
- One-liner by default. `@param`/`@returns` only when non-obvious. `@example` for tricky usage. `@internal` hides, `@deprecated` marks removal.
- Keep minimal: the jsdoc lint is deliberately loose (`require-param`, `require-returns`, `tag-lines` off). Don't write JSDoc types — `jsdoc/no-types` is on, TypeScript provides them.

## Pipeline

1. `packages/<pkg>/typedoc.json` + `typedoc*` devDependencies (catalog).
2. `pnpm build-docs` → `scripts/build-docs.mjs` runs TypeDoc once per package into `apps/playground/.generated/api-docs/<pkgDir>/` (flat `README.mdx` + one `<dot.path>.mdx` per module; gitignored).
3. A custom loader (`apps/playground/src/content/loaders/api-docs.ts`) reads that dir and serves it as the `api` content collection — a package entry from the README frontmatter plus one entry per module.
4. `apps/playground` (Astro) renders one page per package at `/discoveries/<pkgDir>/`: the README overview (`#overview`) plus every module as an anchored section (`#<module-path>`), navigated by an in-page scrollspy sidebar.

Config templates: `packages/glaze/typedoc.json` (React, `@types/react` mapping), `packages/randomart-engine/typedoc.json` (non-React, `@types/node`), `packages/art-canvas/typedoc.json` (app: single entry point file). Glaze is the *config* template, not a style authority.

## Maintenance

API changes → regenerate, nothing to edit. Update the README only when *concepts* change. Re-run: `pnpm build-docs`.
